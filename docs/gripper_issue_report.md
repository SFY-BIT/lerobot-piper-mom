# 夹爪"闭合又张开"问题 —— 完整诊断报告

**日期**: 2026-08-03
**任务**: stamp seal（印章按压）
**模型**: Pi0Force 双头模型（含力，30步 action chunk，DeltaActions + AbsoluteActions 输出）
**客户端**: `piper_force_client.py`（ZMQ, port 5555）或 `piper_ws_force_client.py`（websocket, port 8000）
**数据集**: `stamp_seal_v2`（30 episodes，夹爪范围 0.000~0.080，闭合=小值）

---

## 1. 现象描述

机械臂移动到印章上方 → 夹爪闭合 → 合拢到极小宽度（≈0.002，完全闭合）→ **立即又张开** → 重新寻找 → 再次到位 → 再次闭合 → 再次张开 → 循环往复，**始终无法形成"抓住印章并保持"的状态**。

用户预期行为：
```
搜索印章 → 到位 → 夹爪闭合到固定宽度(≈0.029，印章挡住) → 保持闭合 → 按压 → 任务结束张开
```

实际行为：
```
搜索 → 闭合到 0.002（完全闭合，抓空）→ 张开 → 再搜索 → 再闭合 → 再张开 ...
```

## 3. 数据集分析（stamp_seal_v2，30 episodes）

### 3.1 夹爪闭合宽度分布

| 类别 | 数量 | 夹爪最小值 | 说明 |
|------|------|-----------|------|
| 正常闭合 | 30 段 | 0.028~0.031 | 印章挡住夹爪，停在固定宽度 ≈0.029 |
| 异常空抓 | 3 段 (ep0, ep16, ep21) | <0.02 | 完全闭合，无印章 |

**正常 episode 模式**（如 ep1, ep12）：
```
起始张开 0.079
  ↓ 到位后闭合
action = 0.000（持续命令全闭合）
state  = 0.029（印章物理挡住，停在 0.029）
  ↓ 保持 300~900 帧（action 一直 0.000，Fz 保持按压）
  ↓ 任务结束才张开
```

**异常 episode 模式**（ep16, ep21 —— 用户故意保留用于"重新寻找"）：
```
闭合到 0.000~0.002（完全闭合，抓空）
  ↓ 立即张开 0.03→0.05（重新寻找）
  ↓ 再次闭合到 0.029（第二次成功抓住）
  ↓ 保持 → 结束张开
```

### 3.2 力信号对比（能否区分"夹住"和"抓空"？）

```
正常夹住(0.029)时 Fz:  +0.31 ~ +5.34  (中位 3.50)
空抓(0.002)时    Fz:  +1.66 ~ +6.70  (中位 5.55)
                              ↑ 分布完全重叠!
```

| 特征 | 正常夹住 | 空抓 | 区分度 |
|------|---------|------|--------|
| Fz | +0.31~+5.34 | +1.66~+6.70 | ❌ 重叠 |
| Fy | -5.3~-6.3 | -5.9~-6.7 | ❌ 重叠 |
| **Fx** | **-0.8~-1.2** | **≈0.0** | ⚠️ 唯一微弱区分 |

**结论**: 模型**无法仅凭力信号区分"抓住印章"和"抓空"**。唯一的微弱信号是 Fx（夹住时 ≈-1N，空抓时 ≈0N），但幅值小、易被噪声淹没。

### 3.3 数据集中 action 与 state 的不一致（关键！）

```
正常抓取时:
  action(夹爪) = 0.000   ← 模型输出的指令是全闭合
  state(夹爪)  = 0.029   ← 物理上被印章挡住
```

**模型学到的是**: "要抓取就输出全闭合指令(0.000)，期望物理上停在 0.029"。

**但推理时**：如果印章不在夹爪间（模型没对准/提前闭合），全闭合指令导致物理闭合到 **0.002**。而 0.002 这个状态在训练数据里**只出现在"空抓"片段**，模型对该状态的响应是"张开重新找"。

---

## 4. 根因分析

### 现象本质

**推理时夹爪闭合的物理结果(0.002)与训练时"成功抓取"的物理结果(0.029)不一致**，导致模型进入它认为的"失败状态"，触发"张开重新寻找"。

### 三个层面的问题

1. **状态歧义**: 训练数据里"0.029=抓住"和"0.002=空抓"是不同的物理状态，但模型对"0.002"的泛化只有"空抓→张开"一个方向（因为只有 3 个空抓片段，全指向张开）。

2. **力信号不可分**: 力传感器数据（即便增加训练占比）也无法让模型区分"夹住"和"空抓"——因为 Fz/Fy 分布完全重叠，只有微弱的 Fx 差异。

3. **闭合时机/定位**: 推理时模型在**印章不在夹爪间**的时候就闭合了（闭合→空抓→0.002）。数据集里闭合总是发生在印章已在夹爪之间（人引导的时序），模型没有学会"先视觉定位印章→再闭合"的强关联。

### 为什么"增加 FORCE 占比"不能解决问题

- 力信号本身不区分"夹住 vs 空抓"（重叠分布），增加占比不会产生新的区分信息
- 问题的核心是**动作-物理反馈闭环**（闭合后停在 0.029 需要印章物理存在），不是力特征的权重问题

---

## 5. 结论：是否数据集问题？

**是，但不完全是。** 问题由数据与物理环境的共同作用导致：

| 因素 | 是否数据集问题 | 说明 |
|------|--------------|------|
| 空抓样本太少(仅3段) | ✅ 是 | 模型对"空抓"状态的响应泛化不足 |
| "闭合→成功"的时序绑定弱 | ✅ 是 | 需要更多"视觉定位→到位→闭合→保持"完整闭环 |
| 力信号无法区分 | ✅ 是(特征层面) | 训练数据里夹住/空抓的力分布重叠 |
| 推理时物理上没印章可夹 | ⚠️ 部分是 | 即使数据完美，模型闭合时机错误也会空抓 |

---

## 6. 建议

### 方案 A：数据层面（推荐，长期）
1. **重录数据时强化完整闭环**：每个 episode 都要包含明确的"搜索 → 视觉定位 → 到位 → 闭合(停在0.029) → 保持 → 按压 → 张开释放"，且闭合动作与"印章在夹爪间"的视觉/力特征强绑定
2. **增加"空抓后重新寻找并最终成功"的样本**（至少 10+ 段，目前仅 3 段），并确保**重新寻找后一定以成功抓取结束**，让模型学到完整循环而非"张开→循环"死循环
3. **保持印章位置可变**（用户已有此设计），但确保相机视野能清晰看到印章
4. 力信号建议：检查 Fx 作为"夹住检测"特征是否可靠；或在数据里标注"抓取成功/失败"标签供后续处理

### 方案 B：客户端 workaround（短期验证）
- 在客户端加"闭合到位检测 + 保持"逻辑：检测到夹爪闭合到阈值且力传感器出现接触信号(Fx/Fz突变)时，锁定夹爪指令不再执行"张开"，直到任务结束或手动释放
- 这可以验证"是否是模型闭合时机问题"，但不能根治

### 方案 C：模型侧
- 检查训练配置：确认 wrench_history 是否真的生效（客户端发 60 帧历史 vs 只发当前帧）
- 考虑给夹爪单独的动作 mask 或提高夹爪维度在 loss 中的权重（如果模型对夹爪不敏感）

### 7.4 综合对比

| 模型 | 离开初始位 | 朝向印章 | 夹爪闭合 | 主要问题 |
|------|-----------|---------|---------|---------|
| **token1 (42000)** | ✅ | ✅ | ✅→张开循环 | 抓空后重找死循环 |
| **full16k** | ❌ 爬行/抖动 | ❌ | ❌ | 原地旋转, 不平移 |
| **lora16k** | ✅ 大幅移动 | ❌ 漂移/缩回 | ❌ | 单调漂移或扫出缩回, 找不到印章 |

### 7.5 关键发现

1. **步数影响行为**：lora16k 10步=单调漂移冲出；30步=扫出缩回原地打转。两种都到不了印章
2. **所有新模型(16k)夹爪都不闭合**：full/lora 16k 全程保持张开，和 token1 的"闭合→张开"是不同缺陷
3. **token1 (42000) 反而是唯一会"到位+闭合"的**，缺陷只在闭合后张开
4. **推理延迟**：full/lora 16k 都是 0.56s/次（期望 0.33s），2Hz 推理达不到
5. **共同待查**：server 侧 wrench_history(60帧力历史) 是否正确发送；16k 模型的视觉输入是否正常
